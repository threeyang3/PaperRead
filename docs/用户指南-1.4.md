# PaperFlow 1.4 用户指南

PaperFlow 是运行在 Obsidian Vault 中的论文采集、分析、阅读和关系整理工具。定时任务由 `PaperFlow Automation` 插件在 Obsidian 内执行，不依赖 Windows 计划任务。抓取论文、分析论文、配置 Agent、订阅同步、图片修复和维护是彼此独立的功能入口，不是线性流程。

## 首次使用

1. 安装 Python 3.11+、Obsidian、官方 Form Flow 0.0.8+。
2. 安装 PaperFlow wheel 或 portable 包。
3. 执行：

   ```powershell
   paperflow init --vault "D:\你的Vault"
   paperflow integration install
   paperflow doctor
   ```

4. 在 Obsidian 中启用 `form-flow` 和 `paperflow-automation`，打开“PaperFlow 控制中心”。

控制中心优先提供论文导入与发现、已有论文分析、阅读队列、Agent/模型设置、ChatGPT 网页分析、图片修复、订阅与数据源、关系图谱、更新、Doctor、audit 和冲突处理。Agent 设置不会被错误地显示为论文抓取的“下一步”。

## 中文显示和论文标题

当 Obsidian 语言为中文时，控制中心、属性显示名、模板说明和诊断尽量使用中文。YAML 的稳定机器字段名仍保持英文，便于迁移、查询和跨语言复现。论文英文原文、摘要、引文和图注不会被刻意翻译。

`paper_title` 保存来源标题，`paper_title_display` 只修复编码和 LaTeX 数学显示。例如：

- 来源标题：`$π_{0.5}$: a Vision-Language-Action Model...`
- 显示标题：`π₀.₅: a Vision-Language-Action Model...`

## Agent 和分析渠道

控制中心可独立设置 Provider、模型、推理强度、超时和回退 profile：

- Codex CLI：只读沙箱，输入为暂存文本。
- Claude Code：禁用工具，仅读取暂存文本；可使用本机已配置的 MiMo 模型。
- ChatGPT Web：使用 Playwright 驱动专用 Edge 配置目录，只上传 `.paperflow/runtime/staging` 中的 PDF 副本。
- Mock：用于离线测试。

ChatGPT Web 默认禁止上传。启用前需要在控制中心确认“允许向 ChatGPT 上传论文 PDF”，并在专用 Edge 窗口手动登录。程序不会保存密码。若遇到验证码、无法识别模型菜单或无法确认最高强度模型，任务会安全暂停，不会静默降级。

## 图片和关系图谱

图片数量是自适应的：优先覆盖架构、方法、实验、结果和任务上下文，去除高度重复图片，边际价值不足时停止。12 张仅是安全上限，不要求选满，没有合格图片时允许为 0。

主题、方法和数据集默认生成实体笔记。`paper_cites` 只投影已验证且已导入本地的引用；未导入标识进入 `paper_citation_ids`；`ai_related_papers` 表示语义相关而非引用事实。反向引用由 Obsidian backlinks 动态形成。

控制中心“高级工具 → 重建关系图谱”会安全重渲染全部论文并更新关系派生层；命令行等价命令是 `paperflow rebuild-relationships`，可先用 `--dry-run` 查看范围。

## 自动化、订阅和更新

Obsidian 打开时，插件可按设置自动：

- 同步已启用的 Feed 订阅；
- 处理 Form Flow 产生的 Inbox 请求；
- 在数据源主机上构建、校验、隐私扫描并发布 Feed（必须先显式授权）；
- 检查 PaperFlow GitHub Release，下载并校验 SHA256，等待用户确认后安全升级。

程序更新与 Workspace/模板/插件迁移分开执行，应用更新前会备份并保留回滚信息。

## 常用检查

```powershell
paperflow health
paperflow doctor
paperflow audit
paperflow migrate verify-workspace-v2
paperflow paper validate
```

出现 Nutstore 冲突文件或笔记在渲染期间被外部修改时，PaperFlow 会拒绝覆盖，并在 `50 Inbox/Manual Review` 保存拟生成版本。
