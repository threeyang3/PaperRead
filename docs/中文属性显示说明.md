# PaperFlow 中文属性显示说明

本文档适用于 PaperFlow 1.3.1 及以上版本，介绍 Obsidian 中文界面中的
论文属性显示方式、设计原因和常见问题。

## 功能概览

当 Obsidian 系统语言以 `zh` 开头时，PaperFlow Automation 会在原生
“笔记属性”面板中为生成的论文属性显示中文名称。目前覆盖 78 个稳定属性，
包括论文元数据、AI 分析结果、用户阅读状态和系统维护信息。

常见示例：

| 中文显示名 | 底层 YAML 键 | 含义 |
| --- | --- | --- |
| 论文唯一标识 | `paper_uid` | PaperFlow 内部使用的稳定论文 ID |
| 论文标题 | `paper_title` | 来源提供的原始论文标题 |
| 作者 | `paper_authors` | 来源提供的作者列表 |
| 摘要 | `paper_abstract` | 来源提供的原始摘要 |
| 主要主题 | `ai_topic_primary` | AI 判断的主要研究主题 |
| 相关性评分 | `ai_relevance_score` | 论文与研究方向的相关程度 |
| 相关性依据 | `ai_relevance_reason` | 相关性判断理由 |
| 阅读状态 | `user_reading_status` | 用户自己的阅读进度 |
| 复现状态 | `user_reproduction_status` | 用户自己的复现进度 |
| 导入时间 | `system_imported_at` | PaperFlow 导入记录的时间 |

## 为什么底层键仍然使用英文

中文名称属于显示层，Markdown frontmatter 中的真实 YAML 键不会被重命名。
这样可以同时保证：

- 现有论文笔记、Bases、查询和模板继续可用；
- Raw、AI、User、Derived 四层数据可以稳定迁移和重建；
- Public Feed 与其他 PaperFlow Workspace 保持兼容；
- 脚本和第三方工具不必为不同界面语言维护两套字段；
- 用户已有的 `user_*` 属性、标签和笔记不会被批量改写。

在属性名输入框获得焦点时，PaperFlow 会暂时显示真实英文键，便于诊断和
精确查询；失去焦点后恢复中文名称。

## 哪些内容不会自动翻译

属性名称会本地化，但以下论文内容保持原文：

- 论文标题、作者姓名和发表场所；
- 摘要、引用、原文摘录和 PDF 提取文本；
- arXiv 分类、数据集名称、模型名称和代码仓库名称；
- AI 输出中明确引用的论文原文。

这样可以避免机器翻译改变学术含义，也方便直接搜索和引用原论文。

## 启用条件

1. 使用 PaperFlow 1.3.1 或更高版本。
2. 在 Obsidian 的“设置 → 关于 → 语言”中选择中文。
3. 启用社区插件 `PaperFlow Automation`。
4. 升级插件后重新加载插件或正常重启 Obsidian。

如果将 Obsidian 切换为英文，重新加载插件后会恢复显示底层英文属性名。

## 验证与排错

先确认版本和集成状态：

```powershell
paperflow --version
paperflow doctor
paperflow audit
```

若属性名仍显示为英文：

1. 确认 `paperflow --version` 不低于 `1.3.1`；
2. 确认 Obsidian 当前语言是中文，而不只是操作系统语言为中文；
3. 在 Obsidian 命令面板运行“重新加载应用”或正常退出后重新打开；
4. 确认 `PaperFlow Automation` 插件已启用；
5. 运行 `paperflow integration status paperflow-automation` 检查资源版本。

中文标签只改变界面呈现，不会编辑论文 Markdown、改写 frontmatter，也不会
触发论文重新分析、Feed 发布或数据迁移。
