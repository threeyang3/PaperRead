# Research Memory — reviewed preview, 2026-11-13

This is an opt-in, original PaperFlow implementation. No code from the supplied
Awesome GPT XPI, userscript or browser extension has been embedded. It does not
claim compatibility with `/zoterogpt` and does not inspect browser sessions,
private network protocols, cookies or hidden reasoning.

## What actually runs

Zotero: choose **PaperFlow：研究记忆（无需 Core）** from the existing item menu.
Obsidian desktop: run **研究记忆：对话、证据与结论（无需 Core）** in the command palette.
The new panel needs neither Python Core nor Codex/Claude CLI. Existing legacy
PaperFlow commands are unchanged and may still require Core.

Create a conversation, enter a canonical arXiv/DOI identity, and save explicit
material snapshots. A snapshot is an abstract, excerpt or personal note, with
its own SHA-256 and a user-supplied version/locator. This is NOT proof that a
whole PDF was read or that an asserted page locator is correct. The panel does
not automatically extract PDFs, images or Zotero annotations in this preview.

The API endpoint must be the full HTTPS Chat Completions URL. Enter a supported
model and key. Credentials live only in the open panel's memory and are cleared
on close. Every API action has an explicit transmission/cost confirmation;
there are no background scans, implicit sends, automatic retries or model tools.
The API gets only the current question and explicitly selected snapshots.
Historical conversation turns are not silently sent in bulk.

Select completed messages to propose research insights. Model output can create
candidates only; it cannot approve, publish, execute code or write arbitrary
paths. Exact-quote matching checks supplied text, not the truth of a conclusion.
Paper-claim acceptance requires both a source quote and explicit human review.
Personal-note text cannot serve as paper-claim evidence.

## Browser file relay (not automatic website control)

1. Export a question JSON package; it includes the question, selected excerpts,
   request identity and an empty answer contract.
2. Use the materials in a browser AI service within its supported integration or
   export options. This software does not send to or scrape the browser.
3. Fill the answer contract with the visible answer. Preserve conversation ID,
   request ID, prompt hash and provider. Mark incomplete answers `partial`.
4. Paste the resulting JSON in the panel and import. Wrong-request, cancelled,
   conflicting and replayed answers are handled explicitly. A partial answer is
   retained but cannot enter automatic distillation.

This reply file is correlation data, not a cryptographic attestation from an AI
provider. It says which question the user associates the answer with, not that
a remote site read every attachment.

## Persistence and privacy

Shared source: `integrations/shared/research-memory/`. The two plugin directories
contain generated byte-identical copies so that each installs independently.
Run `python scripts/sync_research_assets.py --check` before packaging.

Each conversation has immutable numbered JSON revision snapshots with integrity
checksums. A new revision is published without overwriting an existing one.
Concurrent writers get a conflict and must reload; corrupt latest records are
reported, not silently reset. Temporary incomplete writes are not visible as
committed revisions. This is local persistence, not multi-device sync.

Default locations:

- Obsidian: `~/.paperflow-private/research/<vault-path-hash>/`, **outside the Vault**.
- Zotero: `<Zotero data directory>/paperflow-research-private/`, separate from
  `storage`, the database and ordinary item notes. No SQLite access.

These are local plaintext records, NOT encrypted storage. They are private by
placement and file permissions where supported, not cryptographic protection.
A local administrator or a custom backup can read them. Network filesystems and
cross-device sync-folder concurrent writes have not been accepted/tested.

Reads load only the selected conversation; list pages load at most 50 summaries.
A record is capped at 4 MiB, 500 messages, 100 contexts, 250 requests and 200
insights. Historical revisions consume disk over time; no automatic destructive
compaction runs. Split large conversations rather than silently truncate them.

## Cross-app export/import and human edits

Private JSON export carries full records and context links. Import preserves
per-message context references, strips executable pending jobs, downgrades
external review/publication grants to candidates, and preserves partial status.
Identical bundle imports reuse the same imported record. A changed bundle becomes
a separate revision archive; this is not automatic cross-device graph merging.

Markdown export creates a new version-named file and never overwrites an
existing note. Generated copies do not edit `explainer.zh-CN.md` or `dialogue.md`.
A future reviewed merge workflow can incorporate them. Raw model HTML, images
and commands are exported as literal text rather than rendered executable HTML.

A public projection includes only accepted insights for which the user wrote and
explicitly approved separate public text. It excludes original chats and excerpt
quotes. The user still needs to review the publication text for private research
content; a structural allowlist does not guarantee semantic anonymization.
Nothing is automatically uploaded to either public GitHub data repository.

## Packaging

Full plugin ZIP/XPI packages carry all local modules. The workspace installer
copies them with its existing hash/backup/manual-edit protection. The official
Obsidian `dist/main.js` artifact is bundled using `scripts/bundle_research.py` so
that three-file Obsidian installation does not require unshipped module files.
No new version tag, production release or CI job was created for this preview.

## Local validation and remaining acceptance

Run without CI or network:

```sh
python scripts/sync_research_assets.py --check
node --test tests/research_memory/*.test.cjs
PYTHONPATH=src python -m pytest tests/research_memory/test_api_review.py
python -m compileall -q src scripts
```

Tests include local journal races/corruption, a mocked Mozilla IOUtils contract,
manual relay replay/cancellation, private import trust downgrade, source-scoped
quotes, public projections, mock API boundaries, headless panel actions and
bundle/module resolution. Mozilla's IOUtils interface was checked against its
published WebIDL and migration guide; a mocked contract is not a native Zotero
test. This preview still requires actual Zotero/Obsidian/API-key acceptance.

No automated browser Bridge, cloud schedule, auto-GitHub publishing, full PDF
citation verification, direct native Zotero child-note creation, mobile port or
full legacy-Core migration is claimed. The old onboarding draft PR is not merged
by this change.
