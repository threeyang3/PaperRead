# PaperFlow 1.5 迁移指南

1. 关闭正在运行的 PaperFlow 作业，等待同步稳定并处理 `-冲突` /
   `-NSConflict` 文件。
2. 运行：

   ```powershell
   paperflow health
   paperflow migrate workspace-v3 --dry-run
   ```

3. 检查每篇 PDF 的 from/to/version、缺失文件和 `deletes_old_pdfs=false`。
4. 应用并验证：

   ```powershell
   paperflow migrate workspace-v3 --apply
   paperflow migrate verify-workspace-v3
   paperflow workspace validate
   paperflow paths validate
   paperflow doctor
   paperflow audit
   ```

迁移先完整备份 `.obsidian`、Workspace、User/Annotation/Community 数据、笔记、
图片、状态数据库和全部 PDF，并生成逐文件 SHA-256 manifest。旧 PDF 不删除；
当前 PDF 复制到 vN 路径，记录更新后建立 pdf-index。已有论文笔记随后统一经过
`compose_record` 和中央渲染器重建，保留 User sidecar、全部 `user_*`、用户标签
及 `USER_NOTES_START/END` 内容。`verify-workspace-v3` 同时检查 PDF 哈希、索引、
论文笔记 frontmatter 与正文 PDF 链接。迁移还会新建私有标注/评审、只读社区
缓存/outbox 和 Bases。网络请求、AI 调用和公共 PR 均为 0。

Derived 层在 compose 时会覆盖聚合兼容记录，因此迁移必须先原子更新 Derived
中的 `paper_pdf_path` 以及 extraction 内受控的 `pdf_path` / `source_pdf_path`，
再重渲染。视觉 asset 的 `path` 是 PNG 路径，保持原样；manifest v1 只通过
`pdf_sha256` 绑定源 PDF，同一字节复制到 vN 后无需改写哈希。

## 修复已应用但验证失败的 schema 3 Workspace

`workspace-v3 --apply` 可安全重入。若 Workspace 已是 schema 3，它不会再创建
一个可能遮蔽原始迁移备份的新快照，而是要求并复用现有
`pre-paperflow-1.5-*` 正式备份，修正 Derived 路径并重渲染全部已有论文笔记：

```powershell
paperflow migrate workspace-v3 --dry-run
paperflow migrate workspace-v3 --apply
paperflow migrate verify-workspace-v3
```

dry-run 中应看到 `repair_mode=true` 和待处理的 `derived_repairs`。成功状态为
`repaired`；若最终验证仍不干净，状态为 `verification-failed`，CLI 返回非零，
且原始备份继续保留。不要手改批量论文 JSON 或 Markdown。

## 安全回滚

回退入口默认只预览，并且只接受 `.paperflow/backups/pre-paperflow-1.5-*` 下
包含 PDF 的正式 SHA-256 备份：

```powershell
paperflow migrate rollback-workspace-v3 --dry-run
paperflow migrate rollback-workspace-v3 --apply
```

也可用 `--backup .paperflow/backups/pre-paperflow-1.5-YYYYMMDD-HHMMSS`
显式选择备份。回滚只恢复 manifest 中已复制且哈希匹配的文件；不会删除备份中
不存在的路径，因此迁移后新增的标注、评审或其他用户文件会原样保留。版本化
PDF 和其他无法安全证明应删除的文件也会保留。不要用 Git 覆盖 Vault 用户内容。

2026-07-21 的真实 `ArxivLearn` 首次 v3 apply 已完成 32 个 record、PDF copy
和 note render，但因 Derived 层仍保留旧 PDF 路径而出现 32/32
`note_link_mismatches`。PaperRead 已加入上述可重入修复和回归测试；真实 Vault
仍须安装包含本修复的新 wheel 后执行 repair、verify、Doctor 与 audit。
