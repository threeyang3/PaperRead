# 论文图片处理说明

PaperFlow 1.5.0 会优先从 arXiv HTML 阅读页下载有原文图注支撑的原始图片，
HTML 不存在、单个 Figure 含多张子图或资源校验失败时，再从本地 PDF 裁剪，并在论文
笔记靠前位置生成“论文视觉导读”。系统优先选择架构图、框架图、方法总览和
流水线图，再补充关键结果图与任务/硬件图；数量由质量、语义覆盖和去重结果
自适应决定，12 张只是控制笔记体积的安全上限，并不要求选满。

## 自动处理流程

1. 导入论文并校验 PDF；
2. 查找以 `Figure`、`Fig.`、`Extended Data Figure` 或 `图` 开头的原文图注；
3. 在全论文范围按图号去重，并区分架构、结果和普通论文图；
4. 以质量、语义类型覆盖和图注相似度逐张计算边际价值，价值不足时停止，
   不用低可信截图凑数；
5. 对 arXiv 论文访问版本固定的 `https://arxiv.org/html/<id>vN`，按图号匹配
   单图 Figure，并只接受同一 arXiv HTML 路径下、通过 PNG 解码与体积限制的资源；
6. 找不到可靠 HTML 原图时，根据图注位置、PDF 图片对象和矢量绘图区域计算裁剪范围；
7. 对架构与总览图采用更保守的上边界，优先保证完整；普通图按单栏或整栏边界
   紧凑裁剪，减少相邻正文；
8. 将 PNG、页码、原文图注、尺寸、SHA256、`source_type` 和可选
   `source_url` 写入可重建的派生层；
9. 在中英文论文模板中按“架构/方法、实验/结果、任务/硬件”分组显示；
10. 原文图注默认折叠，每张图都提供 HTML 原图来源和/或直达 PDF 页码的链接。

图注和图内文字保持论文原文，不做机械翻译。中文 Obsidian 会显示中文章节
名称与类型说明，但不会改变学术原意。

## 在 Base 中按图片浏览

`Paper Library.base` 提供两个与表格并列的卡片入口：

- “视觉浏览”：显示全部带视觉导读的论文；
- “触觉论文”：只显示主要主题或主题列表包含 `Tactile Sensing` 的论文。

卡片封面使用 Base 公式 `file.embeds[0]` 读取论文笔记的第一张嵌入图。因为
模板把架构/方法图排在其他图片之前，封面会优先展示架构、系统或方法总览。
卡片只保留标题、作者、年份、主题、评分和阅读状态，完整字段仍在表格视图中。
当 Obsidian 使用中文界面时，卡片通过只读公式别名显示“第一作者”“年份”
“主要主题”“综合评分”“阅读状态”和“优先级”；底层稳定 YAML 键不变。
这两类视图是并列入口，不表示抓取、分析、阅读或 Agent 设置之间存在固定顺序。

## 文件位置与数据边界

假设 PDF 是：

```text
80 Attachments/Papers/2026/2607.15275.pdf
```

图片会写入：

```text
80 Attachments/Papers/2026/2607.15275.assets/
├── figure-1-p1.png
├── figure-2-p4.png
└── manifest.json
```

`manifest.json` 遵循 `schemas/visual-assets.schema.json`，记录论文 UID、
PDF SHA256、图号、页码、分类、原文图注、Vault 相对路径、图片尺寸、图片
来源和图片 SHA256。图片和清单属于 Derived 层：

- 不新增或改名论文 YAML 属性；
- 不进入 Raw、AI 或 User 数据；
- 不进入 Public Feed；
- 可以从原始 PDF 重新生成；
- 不覆盖 `user_*`、用户标签或 `USER_NOTES_START/END` 中的内容。

## 现有论文补齐图片

在 Obsidian 控制中心点击“补齐论文图片”，或运行：

```powershell
paperflow paper visuals --all
```

处理单篇论文：

```powershell
paperflow paper visuals arxiv:2607.15275
```

默认采用自适应选择。需要限制时可使用 `--max-assets 0..12`。从旧模板
升级到模板 v6 并重建 HTML 优先图片时使用正式视觉迁移命令：

```powershell
paperflow migrate visual-assets --apply
```

迁移会先获取 Workspace 全局锁并创建完整 Workspace 备份，再刷新派生图片与论文笔记。
官方模板 v3 可安全升级；如果检测到自定义模板，迁移不会覆盖它，而会生成
`.new` 文件供人工合并。

## 质量与限制

- 只提取能关联到可靠图注的内容；找不到时返回
  `no-captioned-figures`，不会生成虚构示意图。
- arXiv HTML 并非覆盖所有历史论文，且组合子图可能由多个文件组成；此时会
  安全回退到 PDF 裁剪，不会拼接或猜测图片。
- 复杂 PDF 的图形可能由图片、矢量路径和文本共同组成。架构图因此采用较
  宽松的裁剪范围，可能包含少量页眉或留白。
- 提取数量是上限而不是目标；整篇只有 5 个可靠图注时只会生成 5 张图。
- 扫描版 PDF、异常图注格式或跨页大图可能需要人工查看原 PDF。
- 原 PDF 更新后可再次运行命令；清单中的 PDF 和图片 SHA256 可用于核验。

## 首批真实样本验收

当前 29 篇具身智能与触觉样本共生成 166 张可追溯 PNG，每篇 3–6 张；
29 篇均通过视觉清单、文件路径、PDF SHA256 与图片 SHA256 校验。其中新增的
π0、FAST 和 π0.5 各提取 6 张图片。Obsidian 1.12.7 实测可在“视觉浏览”中显示
29 张关键图封面，运行时和控制台均无错误。
