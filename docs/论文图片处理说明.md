# 论文图片处理说明

PaperFlow 1.3.2 会从本地 PDF 中提取有原文图注支撑的关键图片，并在论文
笔记靠前位置生成“论文视觉导读”。系统优先选择架构图、框架图、方法总览和
流水线图，再补充关键结果图；默认每篇最多保留 3 张，避免把整篇论文变成
无重点的截图集合。

## 自动处理流程

1. 导入论文并校验 PDF；
2. 查找以 `Figure` 或 `Fig.` 开头的原文图注；
3. 在全论文范围按图号去重，并区分架构、结果和普通论文图；
4. 根据图注位置、PDF 图片对象和矢量绘图区域计算裁剪范围；
5. 对架构与总览图使用更保守的整页宽度，优先保证图形完整；
6. 将 PNG、页码、原文图注、尺寸和 SHA256 写入可重建的派生层；
7. 在中英文论文模板中使用 Obsidian 内嵌链接显示图片。

图注和图内文字保持论文原文，不做机械翻译。中文 Obsidian 会显示中文章节
名称与类型说明，但不会改变学术原意。

## 文件位置与数据边界

假设 PDF 是：

```text
80 Attachments/Papers/2026/2607.15275.pdf
```

图片会写入：

```text
80 Attachments/Papers/2026/2607.15275.assets/
├── figure-1-p1.png
├── figure-2-p4.png
└── manifest.json
```

`manifest.json` 遵循 `schemas/visual-assets.schema.json`，记录论文 UID、
PDF SHA256、图号、页码、分类、原文图注、Vault 相对路径、图片尺寸和图片
SHA256。图片和清单属于 Derived 层：

- 不新增或改名论文 YAML 属性；
- 不进入 Raw、AI 或 User 数据；
- 不进入 Public Feed；
- 可以从原始 PDF 重新生成；
- 不覆盖 `user_*`、用户标签或 `USER_NOTES_START/END` 中的内容。

## 现有论文补齐图片

在 Obsidian 控制中心点击“补齐论文图片”，或运行：

```powershell
paperflow paper visuals --all
```

处理单篇论文：

```powershell
paperflow paper visuals arxiv:2607.15275
```

默认每篇 3 张。需要调整时可使用 `--max-assets 1..10`。从模板 v2
升级到 v3 时使用正式迁移命令：

```powershell
paperflow migrate visual-assets
```

迁移会先获取 Workspace 全局锁并创建完整 Workspace 备份，再刷新派生图片与论文笔记。
如果检测到未包含视觉段落的自定义模板，迁移不会覆盖它，而会生成 `.new`
文件供人工合并。

## 质量与限制

- 只提取能关联到可靠图注的内容；找不到时返回
  `no-captioned-figures`，不会生成虚构示意图。
- 复杂 PDF 的图形可能由图片、矢量路径和文本共同组成。架构图因此采用较
  宽松的裁剪范围，可能包含少量页眉或留白。
- 扫描版 PDF、异常图注格式或跨页大图可能需要人工查看原 PDF。
- 原 PDF 更新后可再次运行命令；清单中的 PDF 和图片 SHA256 可用于核验。
